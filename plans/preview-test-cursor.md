# Synthetic Cursor for Test Runs in the Preview Panel

**Status:** planned · extends Phase 1 of `plans/iframe-to-webcontentsview.md`

## Summary

When a test runs in the preview panel, Playwright teleports: an element is clicked with no
visible pointer travel, so the run is nearly impossible to follow by eye. We add a synthetic
cursor — a fake pointer drawn inside the driven page — that glides from its current position
to each target along a straight (shortest) path in slow motion, and lands with a visible
click effect (border flash + overlay pulse). The run itself is also slowed so the pacing is
watchable.

Nothing real moves. Playwright still teleports; the cursor is an animation we play _before_
each real action, choreographed from the fixture shim.

## Constraints that shape the design

1. **Nothing can draw over the native view except the page itself.** The WebContentsView
   composites above all renderer DOM, so Dyad's UI cannot overlay a cursor on it. The cursor
   must be DOM injected _into the driven page_.
2. **No new bridge.** The view is deliberately sandboxed (no preload, no IPC). But the test
   run already owns a CDP channel to the page — `addInitScript` / `evaluate` ride that
   channel, so the cursor needs no new privileges and exists only while a run does.
3. **The fixture shim is the only code we control in the test process.** Specs are the
   user's and must stay unmodified. The shim (`e2e-tests/fixtures/dyad/dyad-test.ts`,
   generated by `src/ipc/utils/playwright_bootstrap.ts`) already reroutes `@playwright/test`
   for preview runs — it is the natural interception point for actions.
4. **Everything must stay inert outside preview runs.** Same gate as today:
   `DYAD_PREVIEW_CDP_ENDPOINT` unset → the shim re-exports vanilla Playwright, and none of
   this exists.

## Architecture

Two halves, both generated by the bootstrap alongside the existing shim:

- **Node side (in the shim):** wrappers around Playwright's pointer actions. Before the real
  action, they measure the target, ask the page to animate the cursor to it, await the
  animation, then run the real action and trigger the landing effect.
- **Page side (cursor runtime):** a small script installed via `context.addInitScript` (and
  an immediate `evaluate` for the already-loaded document). It owns the cursor element and
  exposes `window.__dyadTestCursor` with `glide(from, to, duration)` (returns a promise that
  resolves when the animation ends), `press(box, point)` for the click effect, and
  `destroy()`.

Sequence for one `locator.click()`:

```
spec calls locator.click()
  └─ shim wrapper
       1. wait for target visible (skipped when { force } is set)
       2. scrollIntoViewIfNeeded → boundingBox()          [target coordinates]
       3. evaluate: __dyadTestCursor.glide(from, to, ms)  [cursor travels]
       4. real locator.click()                            [Playwright acts as usual]
       5. evaluate: __dyadTestCursor.press(box, point)    [border + overlay flash]
```

## The steps

### 1. Run in slow motion

`chromium.connectOverCDP(endpoint, { slowMo })` — Playwright's own slow-motion option,
supported on CDP connections. The shim reads it from a new env var
(`DYAD_PREVIEW_SLOWMO_MS`, default ~250) that `tests_handlers.ts` sets for preview runs only,
next to where it already sets `DYAD_PREVIEW_CDP_ENDPOINT` (`src/ipc/handlers/tests_handlers.ts:379-391`).
slowMo paces everything (typing, navigation); the cursor animation adds the travel time on
pointer actions specifically.

### 2. Where the cursor currently is

The page runtime owns the cursor's position. Initial position: viewport center, faded in on
first use. The shim mirrors the last position per page (a `WeakMap`) so that after a
navigation — which wipes the page's DOM — the next glide can recreate the cursor at its last
known position instead of resetting to center. `addInitScript` reinstalls the runtime on
every new document automatically.

### 3. Where the target is

`locator.boundingBox()` after `scrollIntoViewIfNeeded()`. Bounding boxes are reported in
main-frame viewport CSS pixels — the same coordinate space the cursor element lives in, even
for elements inside the app's own iframes. No DIP/zoom math needed (that pain is specific to
`setBounds`; here everything stays inside one page). The click point honors the action's
`position` option when given, else the box center. If the element can't be measured within a
small budget (~1s), skip the animation and let the real action handle waiting and erroring
exactly as it would today — worst case is a teleport, never a changed test outcome.

### 4. The path

Straight line from current position to target — the shortest path, per the feature's intent.
Eased (ease-in-out) so it reads as deliberate rather than linear-robotic. Duration
proportional to distance, clamped: `clamp(200, distance × 1.5, 700)` ms. Animated with
`requestAnimationFrame` transforms on the cursor element (GPU-composited, no layout).

### 5. Moving it

The shim calls `page.evaluate` with `(from, to, duration)`; the runtime animates and resolves
its promise at the end; the shim then performs the real action. The cursor element is
`position: fixed`, `pointer-events: none`, max `z-index`, appended to `documentElement` — it
can never intercept the real click or affect the app's layout.

### 6. The landing effect

On click-like actions, immediately after the real action resolves:

- the cursor does a quick press animation (scale down/up),
- the target's bounding box gets a border flash (2px accent outline) plus a translucent
  overlay fill that fades out (~350 ms),
- a small ripple expands from the click point.

Hover gets the glide but no press effect; `{ trial: true }` gets no effect (nothing was
clicked).

## What gets wrapped

Patched once at connect time, on the prototypes reachable from the connected page
(`Object.getPrototypeOf(page.locator("html"))` etc.) — covers every locator regardless of how
it was created (`getByRole`, `frameLocator`, chained):

| API                                                                 | Treatment                                      |
| ------------------------------------------------------------------- | ---------------------------------------------- |
| `locator.click` / `dblclick`                                        | glide + press effect                           |
| `locator.hover`                                                     | glide only                                     |
| `locator.check` / `uncheck` / `setChecked` / `selectOption` / `tap` | glide + press effect                           |
| `page.click`-style convenience methods                              | same, for older-style specs                    |
| `page.mouse.click` / `move` (raw coordinates)                       | glide to the given point                       |
| `fill` / `press` / keyboard                                         | not wrapped in v1 (optional focus pulse later) |
| `locator.dragTo`                                                    | later: press → glide → release                 |
| assertions (`expect(...)`)                                          | never touched                                  |

## Guarantees

- **Semantics unchanged.** Wrappers never swallow errors, never retry, never alter options
  passed to the real action. Every pre-animation step is best-effort with a bounded budget;
  any failure degrades to today's teleport behavior.
- **Inert outside preview.** All of it lives behind the existing `DYAD_PREVIEW_CDP_ENDPOINT`
  gate. Ordinary Tests panel runs, the agent's `run_tests` tool, and `npm test` outside Dyad
  see vanilla Playwright — extend the existing spawned-args/env regression test to prove the
  new env vars are absent there.
- **Clean exit.** Best-effort `__dyadTestCursor.destroy()` at fixture teardown, since the
  page can briefly outlive the run before the view closes.

## Files to touch

- `src/ipc/utils/playwright_bootstrap.ts` — generate the cursor runtime + wrappers (new
  generated file beside the shim, e.g. `e2e-tests/fixtures/dyad/dyad-cursor.ts`, same
  sentinel/regeneration rules); pass `slowMo` in `connectOverCDP`.
- `src/ipc/handlers/tests_handlers.ts` — set `DYAD_PREVIEW_SLOWMO_MS` (and a
  `DYAD_PREVIEW_CURSOR` kill switch) for preview runs.
- Tests: unit tests for path/duration math; bootstrap generation tests (runtime present,
  inert without the env); handler env regression test.

## Open questions / future work

- A visible toggle (Tests panel or Settings) for slow motion / cursor, vs. always-on for
  preview runs in v1 (proposed: always-on — watching is the point of preview runs).
- `dragTo` choreography; keyboard focus pulse on `fill`.
- Respect `prefers-reduced-motion` by replacing the glide with the landing highlight only.
- Curved / humanized paths if the straight line feels too mechanical.
